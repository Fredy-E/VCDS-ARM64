# VCDS-ARM64 v0.1.0 — documentation-only release (draft)

**Status: DRAFT — not published.** No git tag, GitHub release, or artifact has been created. Prepared for maintainer review; publication is a separate, explicitly authorized step.

This is a **documentation-only** release: field notes, official-source references, and validation scaffolding for running genuine, licensed Ross-Tech VCDS on Windows 11 ARM64. It redistributes **no Ross-Tech software** — no code, binaries, firmware, installers, or drivers. References to official native builds are vendor guidance, not repository-built software or an independent compatibility certification.

## What a v0.1.0 release would include

- [SETUP.md](../SETUP.md) — setup path for genuine, licensed hardware (HEX-V2 / HEX-NET), with official-source citations.
- [EVIDENCE.md](../EVIDENCE.md) — the published single-machine observations, the versioned "not recorded" table, and quoted official guidance.
- [TROUBLESHOOTING.md](../TROUBLESHOOTING.md) — the COM-port detection issue, legacy-interface reality, and HEX-NET WiFi caveat on ARM, each labeled by source.
- [REPRODUCTION-TEMPLATE.md](../REPRODUCTION-TEMPLATE.md) — how maintainers record new evidence.
- `tools/check_docs.py` + docs-only CI — dependency-free Markdown link/index checks.

## What it explicitly does NOT include

- No Ross-Tech software, binaries, firmware, installers, or drivers — nothing is redistributed or hosted here.
- No license, activation, or protection bypass — genuine, licensed installations only.
- No compatibility guarantee or hardware validation matrix; evidence is limited to the notes in EVIDENCE.md.

## Evidence scope (summary)

Two published notes from one machine — VCDS 24.x (x86) on Windows 11 ARM64 in USB mode, and COM-port configuration breaking detection — plus cited official guidance. Windows build, interface model/firmware/revision, driver version, and observation date were **not recorded**; see [EVIDENCE.md](../EVIDENCE.md).
